# 🏛 LLM Council — скилл для Claude Code

*[English version →](README.md)*

Задаёшь вопрос один раз — а дальше **несколько моделей отвечают независимо, анонимно рецензируют друг друга, и модель-«председатель» сводит единственный наилучший ответ.**

Порт проекта Андрея Карпаты [`llm-council`](https://github.com/karpathy/llm-council), но работает **целиком внутри Claude Code по подписке**. Без OpenRouter, без API-ключей, без доплат: члены совета — это разные модели Claude (Opus, Sonnet, Fable).

## Как это работает

Три стадии, оркестрируемые инструментом **Workflow** в Claude Code:

1. **Независимые ответы.** Каждый член совета (`opus`, `sonnet`, `fable`) отвечает на вопрос сам, параллельно. Друг друга не видят.
2. **Анонимная рецензия.** Ответы переименовываются в `Response A / B / C` — авторы скрыты — и каждая модель ранжирует их от лучшего к худшему и отмечает фактические ошибки. Анонимность держит оценку честной.
3. **Синтез председателя.** Председатель (`opus`) читает все ответы и все рецензии, разрешает противоречия, выкидывает помеченные ошибочными утверждения и пишет один финальный ответ.

На выходе — **финальный ответ** плюс короткая **сводка совета** (общий ранг и заметные расхождения).

## Установка

Скопируй папку скилла в свой личный каталог скиллов Claude Code:

```bash
git clone https://github.com/selajuf/llm-council-skill.git
cp -r llm-council-skill/llm-council ~/.claude/skills/llm-council
```

Теперь доступно во всех проектах.

## Использование

```
/llm-council Как лучше всего ценообразовать B2B SaaS для рынка ЕС?
```

…или просто скажи *«спроси совет»*, *«дай ensemble-ответ»*, *«пусть несколько моделей это отрецензируют»*. Дескриптор скилла ловит такие формулировки.

**Не** используй для рутинных вопросов — совет спавнит `2N+1` агентов и жжёт токены. Это для важных, неоднозначных или спорных вопросов, где одной модели мало.

## Требования

- **Claude Code** с доступом к нескольким моделям (Opus / Sonnet / Fable).
- Инструмент **`Workflow`** (мультиагентная оркестрация). Скилл использует его как движок — почему, см. ниже.

## Почему Workflow, а не сырые субагенты

В тяжело-нагруженных сетапах (много SessionStart-хуков, льющих контекст в каждого субагента) сырой `Agent`-диспатч с non-`opus` моделью может уйти в чат-режим и **простоять** — ответить *«готов, что нужно?»* вместо ответа по делу. Субагентам Workflow прямо сказано *«твой финальный текст — это возвращаемое значение»*, поэтому они отвечают надёжно. Поэтому совет оформлен как Workflow-скрипт ([`llm-council/run.js`](llm-council/run.js)), а не как параллельные вызовы `Agent`.

## Кастомизация

- Меняй состав / председателя в [`llm-council/run.js`](llm-council/run.js) (`MEMBERS`, модель `chairman`).
- `haiku` намеренно исключён — слаб как самостоятельный член совета.
- Нужен loop-until-consensus или внешние модели (GPT/Gemini)? Расширь Workflow-скрипт.
